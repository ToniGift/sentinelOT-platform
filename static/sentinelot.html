    How it works

    1. 1

      Listen

      A sensor on a mirror port reads every frame between the masters and the PLC. It never writes to the control network.

    2. 2

      Judge

      Rules check who is talking, which function code they used and whether the value fits the engineering limits.

    3. 3

      Explain

      AI adds asset context, maps the activity to MITRE ATT&CK for ICS and tells the analyst what to do first. It recommends and never acts.

    In the live demo a fixed rule raises the alarm and the AI only explains it. The recorded alerts come from the full project, where five AI agents triage each alert and code checks their output. Read the code on GitHub.

    The plant, hosts and traffic on this page are invented and simulated in your browser. No real control system is connected. The recorded verdicts are the ones SentinelOT returned in its evaluation run on 6 October 2026. Level 5, the firewalls, the ERP server, the MES server, the OT domain controller, the DCS (DCS-CTRL-01, its server and operator station), the utilities tank, pump and flow meter, the sealer, the robot and the conveyor motor were added for this demo and aren’t in the project’s asset file. The Alarm limits results come from replaying a generated dataset with labelled faults. They are not measurements from a plant. The What-if tab runs a simplified demo model in your browser, not plant physics: the tank fill, the pump and flow response, the sealer lag and the conveyor backlog are invented for the demo, and nothing is sent anywhere.
